# Security reporting
Report exposed credentials, server/relay vulnerabilities, privacy leaks, unauthorized hidden-card exposure, malicious transfer behavior, and remote-code or filesystem vulnerabilities privately.

**Publication prerequisite:** the maintainer must configure GitHub private vulnerability reporting or a monitored private security contact, then replace this paragraph with verified instructions. No private reporting address or public repository exists yet. Do not invent one, and do not post active serious vulnerabilities as public issues. If testing this local candidate, contact the maintainer through an existing private conversation to arrange a secure report.

Provide affected version, impact and the smallest safe reproduction. Redact credentials and personal information. Do not attach full private libraries, active access tokens or live exploit targets. Allow maintainers a reasonable opportunity to investigate before public disclosure. No response-time guarantee or bug bounty is promised.

Test only systems you control or are authorized to test. The current Beta is the supported development target; no long-term support commitment exists.
