# Pinned future milestone: double-sided cards

Deferred beyond CardLink 7.1. Do not implement until explicitly requested.

Define these together before implementation:

- Front definition and back definition, with explicit artwork references.
- One shared Match Instance ID across both faces.
- Transformed/flipped state separate from tap, face-down and library knowledge.
- Which face each viewer is allowed to see, including public reveal and private knowledge.
- Import/archive naming, pairing, deduplication and deck references.
- Interaction between a physical second face and the configured hidden card back.

Preserve ownership/controller separation, private transfers, save compatibility and the manual kitchen-table rules model.
